## Decision

**Tallow's extraction stack is built Tallow-native, in Rust. REA is used only as an external
CLI, out of process, never inside Tallow's runtime path.** The 2026-10-12 decision ("skip REA
entirely — build only the Tallow-native Rust extraction stack") is re-affirmed, with the
qualification below about what "skip" means in practice.

**Overlap with Tallow's web plane: zero capabilities Tallow lacks** — with one exception,
static JS/Electron analysis, which the external CLI already covers. Of REA's 207 tools, 12
lanes operate on compiled artifacts (dex/APK, native binaries, firmware), which are out of
domain for a web-extraction stack, and two of those lanes are licence-walled.

## The two integration shapes, with their real costs

1. **Rust FFI wrapper.** Puts a Node process **in the extraction path** — a second runtime,
   a second egress surface, and a second failure mode inside the component whose whole point
   is that it is a single, auditable Rust binary. Cost is not the binding constraint; the
   trust boundary is.
2. **In-sandbox integration.** Requires the sandbox image to be rebuilt and the chokepoint
   allowlist extended. **Verified, not assumed:** the sandbox image has **no Node**, so this
   shape is an image rebuild, not a config change.

Both shapes buy capabilities the decision does not need. Neither is free.

## What "skip" does NOT mean

It does not mean "do not use". REA remains a supported **out-of-process** tool for the
lanes Tallow deliberately does not cover (static JS/Electron analysis; compiled-artifact
work). The operating procedure is in
[`REA-CLI-RUNBOOK.md`](../extraction-engine/REA-CLI-RUNBOOK.md). What is excluded is REA
inside Tallow's runtime, and REA as a dependency of any Tallow build.

## New defect found while verifying (recorded, not silently fixed)

The prior audit listed four opt-in feature flags as `parquet-storage`, `s3-storage`,
`redis-backend`, **`real-ml`**. `real-ml` **is not a feature**: `rg real-ml Cargo.toml` → no
matches. Three of the four exist; the fourth was an audit error that propagated into
`CHECKLIST.md`, `RECONCILIATION-2026-10-12.md`, `REA-INTEGRATION-ASSESSMENT.md` and the
2026-07-22 upgrade audit. Worse, `src/main.rs:16273,16292` print **`requires real-ml`** as a
user-facing refusal — the code directs users to a switch that cannot be thrown. Tracked under
`P6.T2`.
