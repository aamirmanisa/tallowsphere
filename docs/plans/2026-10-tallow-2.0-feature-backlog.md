# Tallow 2.0 — feature backlog (100)

Companion to [`2026-10-tallow-2.0-blueprint.md`](2026-10-tallow-2.0-blueprint.md).
**40 network/intelligence features + 60 general-purpose features.** Every entry is a
capability, not a slogan: it names the observable behaviour and the module it lands in.
Size: S ≤ 1 week, M ≤ 3 weeks, L ≤ 8 weeks, for one engineer familiar with the tree.

Existing modules are named so this list cannot re-sell what already ships. Where a
capability exists in weak form, the row says *extends* and states the delta.

## A. Network and intelligence (40)

### A1. Topology (N01–N12)

**Landed:** N01 (raw SYN scan), N10 (per-target/per-prefix rate governor),
N11 (plan-before-run) — `6c66dc6`; N03 (FIN/NULL/Xmas, all reporting
`open|filtered` rather than `open`), N04 (ICMP+TCP discovery union with
per-method confidence) — `97acae8` — and N06 (TLS posture: negotiated
version/cipher/ALPN, chain, leaf fingerprint, certificate SANs, trust reported
as data) — `7a54b8f` — N05 (banner/version from the service's own greeting) —
`9c2d117` — N07 (JA4 computed from the recorded ClientHello) — `b8bba2a` — and
N02 (UDP scan with protocol payloads and ICMP-unreachable reading) — `b1d8823`
— and N12 (cross-technique reconciliation with disagreement surfaced) — current
commit. All in `src/stdlib/topology.rs`, all refusing an unlisted target against
the scope register before a packet is built. N08 (TTL walk with per-hop RTT,
multipath flag and optional offline ASN lookup) — `6c818a7` — adds
`stdlib/topology.tl` so tooling sees the module.

**Adversarial pass (2026-10-26).** A 37-test adversarial suite now runs against
the whole lane (`tests/topology_adversarial.rs`, `68206c4`): every entry point
is checked for refusal of an unlisted target, scope-bypass by literal spelling
(hex, integer, short form, trailing dot), port-spec malformation, and
manifest/dispatch agreement. It found five real defects, all fixed in
`13885a0`: `parse_ports` was declared but not dispatched; `"1,,2"` silently
scanned ports 1 and 2; an Int port wrapped (`70000` → `4464`) in
`banner`/`tls_posture`/`ja4`; and the target was resolved before it was
authorized, so an unlisted hostname was looked up (a DNS query is a packet)
before the scope gate refused it. All entry points now authorize the literal
target first.

Gates at `68206c4`: `topology_scan` 12/12, `topology_adversarial` 37/37,
`--lib topology` 7/7.

**Known limits, measured:** the topology plane has **no codegen lowering** — it
runs on the interpreter, and `tallow run --require-native` refuses it; the
scope register path is resolved **relative to the CWD**, so an invocation from
another directory fails closed with `scope:register-unreadable` rather than
authorizing anything.

**N09 (IPv6) landed** — `aadd095` (branch `ce88998`). The lane is complete with
three amendments the implementation forced, recorded here rather than smoothed
over:

- The v6 raw path is **refused**, not implemented: a raw TCP segment over IPv6
  needs `IPV6_HDRINCL`, which this build does not set. `v6_raw_refusal` names
  the missing capability and points at `v6_connect_scan`, the unprivileged path
  that does work. An empty result would have been a measurement never taken.
- **Discovery is ICMPv6 echo, not NDP.** The backlog row said NDP-based
  discovery; NDP only observes an on-link host, which is a different measurement
  with a different confidence. The row is amended accordingly.
- **Link-local scope ids execute but are not reply-verified here**: this host has
  `::1` on `lo` and no `fe80::/10` address, so `%zone` resolves and one probe is
  sent, but no reply was possible to observe.
- `src/scope.rs` gained `host_key()`: splitting an authority on `:` truncated an
  IPv6 literal (`::1` → `""`, `2001:db8::1` → `"2001"`), so no IPv6 grant could
  be expressed in the register at all. Entry matching stays exact equality or an
  explicit `*.` suffix, so `2001:db8::1` cannot authorize `2001:db8::10`.
- The operational register now carries a `::1` entry on the same self-hosted
  basis as `127.0.0.1` (`f1f5274`, operator-approved). Measured with that
  register, not a fixture: `scope check "::1"` allowed, `"[::1]"` normalises to
  it, `2001:db8::1` still refused, and a live listener on `[::1]:46021` comes
  back `open` with `46023` `closed`.

Gates after the merge: `topology_ipv6` 6/6, `topology_scan` 12/12,
`topology_adversarial` 37/37.

### A5. Evidence and safety (N38–N40)

**Scope-gate adversarial pass (2026-10-26).** The gate that decides whether a
packet may be built had never been attacked, only relied on. `assay` wrote
`tests/scope_adversarial.rs` (15 tests, 595 lines) against it and found five
defects, fixed in `2d95f04`:

- **fail-open:** an unparseable `expires_at` (`"soon"`) loaded and made a grant
  permanent, while `scope verify` reported the register sound. Dates are now
  validated at load; an undateable grant cannot lapse, so it refuses instead.
- **partial authorization:** a `written-consent` entry with no evidence was
  refused per-host but its sound siblings were still authorised, and `check`
  and `verify` disagreed. A defective entry now invalidates the register.
- a malformed port suffix (`host:99999`) was dropped, so the allow was answered
  against a target nobody spelled; it is now `HostMalformed`.
- a bracketed IPv6 grant (`[::1]`) authorised nothing, because register keys and
  targets were normalised differently; one `normalize_key()` now serves both.
- `Example.COM` and `example.com.` reached different decisions for one FQDN.

Gates: `scope_adversarial` 15/15, `--lib scope` 78/78.

**Landed (2026-10-26):** N38 grant-bound export and N39 budget refusal receipts —
`d9dd0c7`, module `intel` (`src/stdlib/intel_evidence.rs` + `stdlib/evidence.tl`).
Export re-consults the register at export time, so a grant that lapsed between
collection and export is refused with the ground named; a record with no target
is a refusal, and `ok` is false if any record was refused so a partial export
cannot read as clean. `budget:unbounded` is an allowed call with no limit, not a
refusal — the distinction the item exists for.

Gates: `cargo test --lib intel_evidence` 12/12, `tallow check stdlib/evidence.tl`
8 items 0 warnings. Dispatch proven from `.tl`, not only from Rust unit tests:
over-limit → `allowed=false code=budget:bytes-exceeded limit=1024 overflow=376`
with a fully populated receipt; within-limit → `allowed=true budget:within`
receipt nil; no limit → `allowed=true budget:unbounded`.

**N40 landed (`d3a88a2`) — A5 is complete.** A secret never serialises without a
recorded declassification: `intel.redact` returns a copy in which every secret
field is replaced by a marker naming the field, never its value; releasing one
requires a declassification naming the field, the reason and the consumer, and
the receipt records exactly that. A declassification without a reason or a
consumer is refused (`redact:no-reason`, `redact:no-consumer`), as is one naming
a field the record does not have (`redact:unknown-field`). Unknown fields pass
through unchanged, and the module docs state which side of the leak/unreadable
trade that takes and why.

Gates: `--lib intel_evidence` 16/16, `tallow check stdlib/evidence.tl` 14 items
0 warnings, `cargo check --lib` exit 0.

Proven from `.tl`, not only from Rust unit tests — `intel.redact` over a real
`crypto.generate_keypair()`:

    redacted_json={"algorithm":"ed25519","private_key":"[redacted:private_key]",
                   "public_key":"cd3726d2…"}
    json_contains_value=false        (the 64-char secret is absent, not masked)
    declassified: released=["private_key"] with a receipt naming reason+consumer
    no-reason  → ok=false            unknown field → ok=false

### B1. Language ergonomics (G01–G15)

**Landed (2026-10-26):** G04 exhaustiveness diagnostics and G08 labeled break
with value — `11216ac` (branch `438d2c8`). G04 names the missing variant at the
match site; a wildcard arm suppresses it, and an unknown scrutinee type says so
rather than listing guesses. G08 gives `break 'outer v` a value: the labeled

mismatch reports at the break site. The AST change (labels on `Loop`/`Break`/
`Continue`) rippled through every match site — 31 files, +1355/−301 — which is
the real cost of the feature, not incidental churn.

Gates: `match_missing` 3, `labeled_break` 3, `break_` 28, `language_ergonomics`

## Sequencing note

The 40 network features are not independently shippable in arbitrary order: N01–N12 depend
on G01 (effect rows) because a scanner without a compile-time scope check is exactly the
class of tool this language exists to avoid. The dependency is stated once here rather than
implied in every row.

G24, G46 and G39 unlock the most downstream work: incremental compilation makes the tooling
features cheap to iterate, structured concurrency is a prerequisite for N10/N11 fan-out, and
structured diagnostics are what the CLI's JSON output and the LSP both consume.
