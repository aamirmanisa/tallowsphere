# Tallow 2.0 — feature backlog (100)

Companion to [`2026-10-tallow-2.0-blueprint.md`](2026-10-tallow-2.0-blueprint.md).
**40 network/intelligence features + 60 general-purpose features.** Every entry is a
capability, not a slogan: it names the observable behaviour and the module it lands in.
Size: S ≤ 1 week, M ≤ 3 weeks, L ≤ 8 weeks, for one engineer familiar with the tree.

Existing modules are named so this list cannot re-sell what already ships. Where a
capability exists in weak form, the row says *extends* and states the delta.

`tallow run tests/fixtures/intel_traffic/smoke.tl`, recorded in §Verification register.)*

Decisions worth keeping:

- **The record carries `payload_sig`, one field beyond the brief's shape.**
  N28's distinction — "https because 443" versus "https because a TLS
  ClientHello" — is the *existence of an observed signature*. A record without
  that field forces the attributor to guess which of the two it is holding, and
  the confidence would be decoration.
- **Port-only evidence is a guess at 0.40, a signature is 0.95/0.90.** The two
  never share a confidence, and `evidence` (`payload` / `port` / `none`) says
  which produced the row. `http` is signature-required: port 80 and 8080 with no
  request/response line render `unknown` with the reason, because port 80 carries
  proxies and tunnels on purpose.
- **One row per unordered 4-tuple per capture**, `src` being the initiator. A
  reused 4-tuple yields one row spanning both connections; splitting per
  connection needs TCP state this module does not keep. Named, not approximated.
- **Timestamp resolution is reported, not smoothed.** `ts_resolution` plus a
  `ts_note` in words, because the stored `*_ms` are truncated microseconds and a
  capture must not claim millisecond precision it does not have.
- **High entropy alone cannot fire.** `ENTROPY_MIN` 3.9 bits/char sits above the
  hex band (uniform hex measures 3.7–4.0 on 16-character labels) precisely
  because hex is also a CDN shard's shape; the gate needs the rate (≥30/min) and
  either an abnormal response ratio or both extremes (≥4.4 bits and ≥120/min).
  The regression test measures a CDN name at 4.49 bits/char and 61 queries/min
  and asserts `fires=false`.
- **A component that was not measured is nil, not zero.** A flow carries no
  qname, so `dns_tunnel_signal(flows)` reports `entropy=null` and
  `entropy_measured=false` instead of scoring a zero that would look like a
  measurement.
- **An absent plane is `unknown`.** `direct` is only ever a reported plane, and
  a word outside direct/tor/mesh renders unknown with the note saying so.

**PCAPNG did not fit the budget** and is refused at offset 0 with
`traffic:pcapng-unsupported`. Classic PCAP, both endiannesses and both timestamp
resolutions, is complete; the block-structured format is a separate item.

### A4. IP intelligence (N33–N37)

**N36 landed** (`f905811`, `67f0a43`) — infrastructure clustering as weighted
evidence, not equality tests. A shared cert scores 0.6, favicon 0.4, header
signature 0.3, **ASN 0.1** and never sufficient on its own: two hosts in one ASN
with no other shared signal stay separate, which is the test that keeps every
Cloudflare-fronted site from becoming one operator. Below the merge threshold a
pair is reported as linked-but-not-merged, so an operator can argue with a
threshold they can see rather than audit a silent union. Each cluster carries the
links that formed it; output is deterministic (byte-identical across runs).

Two things the lane taught, both kept:

- **A stdlib struct cannot be written as a literal in a `.tl` program** (E0115:
  the typechecker only knows structs the program declares). N36's first commit
  therefore declared a surface no program could call — unit tests were green, and
  only running a real program showed it. `ip.observation(...)` is the
  constructor that makes it reachable. Any future stdlib module taking an input
  struct needs the same constructor.
- **`unclustered` had to be added** (`568cafd`): singletons are correctly not
  clusters, but they were dropped without a trace, leaving `observation_count=5`
  against four members. They are now reported, and a test asserts members +
  unclustered == observation_count.

**Landed:** N33 (offline ASN/prefix table — explicit path → `TALLOW_IP2ASN` →
`/usr/share/ip2asn/ip2asn-v4.tsv`; longest-prefix match; `ip:table-missing`

### Five in full

> **G09 — module visibility.** Add a `visibility` field to `Item` (`src/ast.rs`) parsed
> from `pub` / `pub(crate)` / bare, defaulting to private. Resolution happens in
> `resolve_imports` / `resolve_imports_recursive` (`src/main.rs:11275`, `:11323` — both
> verified present), which is where the importing file's module identity is already
> known; the check itself belongs in the typeck pass so both planes agree.
> **Acceptance test** `tests/module_visibility.rs`: three cases — (a) `pub fn` called from
> another file compiles on both planes; (b) bare `fn` called from another file is refused;
> (c) `pub(crate)` compiles inside the crate root and is refused from a dependency package.
> **Refusal semantics:** `tallow check` exits 1 with `item <name> is private to module
> <mod>; mark it pub or move the call` — naming the item, the module and the call site's
> span. No fallback to "assume pub": a visibility pass that defaults open is a no-op.

> **G11 — const generics.** Parse integer literals in type-argument position
> (`src/parser.rs` type-expression path) into a `ConstArg::Int` variant on
> `TypeExprKind::Generic`; typeck monomorphises per distinct integer (same path as the
> existing generic instantiation in `src/typeck.rs`); codegen emits one struct per
> instantiation with the array length folded into the LLVM type.
> **Acceptance test** `tests/const_generics.rs`: `struct Buffer<const N: Int> { data: [u8; N] }`
> — `Buffer<4>` and `Buffer<4096>` in one program produce two distinct types, `size_of`
> differs, and passing a `Buffer<4>` where `Buffer<8>` is expected is refused on both
> planes. Native and interpreter stdout byte-identical.
> **Refusal semantics:** a non-literal const argument (a variable, an expression) is
> refused at parse with `const generic argument must be an integer literal`, exit 64; a
> mismatched instantiation is `E0xxx expected Buffer<8>, found Buffer<4>`, exit 1.

> **G46 — structured concurrency.** New `scope { … }` expression in the parser, lowered to
> a task-group frame in the interpreter (`src/interp.rs`) and to the runtime's existing
> task handle table (`src/runtime/`). A child spawned inside the block is joined before the
> block's value is produced.
> **Acceptance test** `tests/structured_concurrency.rs`: (a) two children writing to a
> shared counter both complete before the block returns; (b) a child that outlives the
> block is a compile error; (c) a panic inside a child surfaces at the block boundary with
> the child's message; (d) interpreter and native agree byte-for-byte on ordering-sensitive
> output.
> **Refusal semantics:** a `spawn` whose handle escapes the scope is refused at typeck with
> `task handle escapes its scope block at <span>` (exit 1). A child still running at block
> exit is joined, never detached — if the join would block forever, the error names the
> stuck child.

> **G58 — typed SQL.** Read a schema file (`schema.sql` or `tallow.toml [sql] schema = …`)
> at check time into a column/type map; check each `db.query::<Row>("SELECT …")` against it
> by parsing the statement with the existing SQL tokeniser. Runtime already has
> `rusqlite` (`Cargo.toml:36` — verified); this item adds only the check-time half.
> **Acceptance test** `tests/typed_sql.rs`: an unknown column, a `WHERE` on a `TEXT` column
> compared to an `Int` literal, and a `SELECT *` consumed into a struct with a missing
> field each produce exactly one diagnostic naming the column and the schema line; a valid
> query compiles and returns the right row on both planes.
> **Refusal semantics:** `tallow check` exits 1 with `sql: column <c> does not exist in
> table <t> (schema.sql:<line>)`; an unreadable or absent schema refuses rather than
> skipping the check (`sql:schema-missing`), because a silent unchecked query is the
> failure mode this item exists to remove.

> **N15 — gRPC reflection.** `grpc.services(target, timeout_ms)` in
> `src/stdlib/intel_api.rs` (dispatch arm `grpc.services`, declared in `stdlib/api.tl`):
> a server-reflection v1 request over HTTP/2, listing fully-qualified services and methods.
> The result carries the **descriptor-set bytes' sha256** and the endpoint that served
> them, so two snapshots are comparable without trusting the server's word.
> **Acceptance test** `tests/grpc_reflection.rs`: against a loopback fixture server that
> serves a known descriptor set — services match, the hash equals `sha256sum` of the
> fixture's descriptor file, and a server with reflection disabled is refused with the
> status code it returned.
> **Refusal semantics:** an unlisted target is refused by the scope register before a
> socket is opened (`scope:` code, as every other `intel` entry point); reflection disabled
> is `intel:grpc-reflection-unavailable (status <code>)`; a non-gRPC response is
> `intel:grpc-protocol-mismatch` naming the content-type. It never returns an empty service
> list — an empty answer is a measurement, and must not be confusable with a refusal.

## Sequencing note

The 40 network features are not independently shippable in arbitrary order: N01–N12 depend
on G01 (effect rows) because a scanner without a compile-time scope check is exactly the
class of tool this language exists to avoid. The dependency is stated once here rather than
implied in every row. G01 is PARTIAL — only `Net` is enforced — so the `Budget` lattice is
the blocking half of that dependency, not the row's existence.

G24, G46 and G39 unlock the most downstream work: incremental compilation makes the tooling
features cheap to iterate, structured concurrency is a prerequisite for N10/N11 fan-out, and
structured diagnostics are what the CLI's JSON output and the LSP both consume. G39 is DONE;
G24 and G46 are OPEN.
