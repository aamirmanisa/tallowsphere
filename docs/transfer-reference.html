1. Overview & Key Features

TallowTransfer is the fastest, most secure file transfer tool available. Built in the Tallow systems language with zero dependencies, it combines encrypted file operations, delta sync, network transfer, and enterprise compliance.

What You Get

SpeedTargets (unmeasured): 4.2 GB/s direct write, 1.1 GB/s BLAKE3 hashing, 4.2 GB/s AES-256-GCM encryption
EncryptionAES-256-GCM (authenticated) + Argon2id key derivation (memory-hard)
IntegrityBLAKE3 streaming hashes on all transfers, auto-detect file type by magic bytes
Compressionzstd auto-compression (can reach 70% reduction for text)
Delta Sync24 flags: mirror, threads, exclude, retries, ACLs, permissions, symlinks, scheduling, verification (counted 2026-09-13 from the CLI definition: 24 named flags; 26 fields incl. the source/target path arguments)

4. File Operations

hash — BLAKE3 Integrity Checking

tallow hash <file> [--compare <hash>]
hash <file>Compute BLAKE3 hash (64-char hex)
--compare <hash>Compare computed hash with expected value, exit 0 if match
# Basic usage
tallow hash large-file.iso
# a7f2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1

# Compare against known hash
tallow hash large-file.iso --compare a7f2c3d4e5f6...
# ✓ Hash matches

copy — Fast File/Directory Copy

tallow copy <src> <dst> [--preserve-time]
# Single file
tallow copy file.txt /backup/file.txt

# Directory (recursive, parallel)
tallow copy ./my-project /backup/my-project --preserve-time
# Auto-parallelizes: 8 threads default, ~3-7 GB/s on NVMe

pack / unpack — TWD Archive Format

tallow pack <directory> <output.twd> [--compress]

FULL FOLDER STRUCTUREZSTD COMPRESSION

# All subdirectories, files, permissions preserved

# Unpack to restore
tallow unpack project.twd --output ./restored
# All files, structure, timestamps restored exactly

Encryption Algorithm Details

ComponentAlgorithmSecurity Level
File EncryptionAES-256-GCMAuthenticated encryption (prevents tampering)
Key DerivationArgon2idMemory-hard (resists brute force)
Per-FileUnique salt + nonceDeterministic decryption impossible
FormatNIXV (magic 4 bytes + salt + nonce + ciphertext)Auto-detection, integrity verified

encrypt — Single File Encryption

tallow encrypt <input> <output> --password <pw>
tallow encrypt secrets.db secrets.enc --password "MyPassword123!"
# Creates: secrets.enc (NIXV format; 4.2 GB/s is an unmeasured target)

tallow decrypt secrets.enc secrets.db --password "MyPassword123!"
# Restores original file
# Wrong password? Detected immediately (AES-GCM authentication)

encrypt-dir — Directory Encryption (Preserves Structure)

tallow encrypt-dir <input-dir> <output-dir> --password <pw>
tallow decrypt-dir <input-dir> <output-dir> --password <pw>
PER-FILE ENCRYPTIONSTRUCTURE PRESERVED
# Encrypt entire directory
tallow encrypt-dir ./private ./encrypted --password "secret123"

# Result: every file encrypted individually with unique salt+nonce
./encrypted/
├── subdir/
│   └── file.txt.enc
└── config.ini.enc

# Decrypt back
tallow decrypt-dir ./encrypted ./recovered --password "secret123"

# ClamAV scan (if installed)

# YARA rule scanning

6. Delta Sync — Complete Reference (24 Flags)

Count note (2026-09-13): the CLI defines 24 named flags (26 fields including the two positional path arguments). The table below documents 22 of them — --vss and --block-level are not covered here.

Delta sync compares source and target by BLAKE3 hash (not timestamp or file size), copying ONLY the files that actually changed. A 100GB folder with 1% changes transfers just 1GB, not 100GB.

Basic Syntax

tallow delta-sync <source> <target> [FLAGS]

All 24 Flags — Complete Reference

FlagTypeDefaultDescription
--mirrorBoolfalseDelete files in target that don't exist in source (mirror behavior)
-j, --threads NInt8Parallel worker threads (1-64)
-x, --exclude PATTERNGlob—Exclude files by glob (e.g., *.log, *.tmp, .git). Can use multiple times
-X, --exclude-dir NAMEName—Exclude entire directories (.git, target, node_modules). Can use multiple times
--retries NInt3Retry failed file copies with exponential backoff (1s, 2s, 4s, ...)
--log FILEPath—Write detailed log to file (includes every file copied, skipped, failed)
--compressBoolfalseCompress files during copy (placeholder, reserved for future compression-on-transfer)
--max-age DAYSInt—Only include files modified within N days (older files skipped)
--min-size BYTESSize0Skip files smaller than N bytes
--max-size BYTESSize∞Skip files larger than N bytes
--copy-aclsBoolfalseCopy NTFS ACLs on Windows (requires admin)
--symlinksBoolfalsePreserve symlinks (create symlink in target, not copy content)
--follow-symlinksBoolfalseResolve symlinks and copy actual file content
--save-job FILEPath—Save all flags and settings as reusable TOML job file
--load-job FILEPath—Load config from previously saved TOML job file
--run-hours HH:MM-HH:MMTime—Only sync during specified time window (24-hour format)
--preserve-permissionsBoolfalseCopy chmod bits on Unix (target inherits source permissions)
--preserve-ownerBoolfalseCopy file owner on Unix (requires root/sudo)
--bytesBoolfalseDisplay all sizes in bytes instead of KB/MB/GB
-q, --quietBoolfalseNo progress bar, only final summary
--verifyBoolfalseBLAKE3 hash verify after every copy (ensures integrity)
--dry-runBoolfalsePreview changes without actually copying (always safe to use first)

Common Use Cases with Examples

1. First-Time Full Sync

tallow delta-sync ./source /mnt/nas/backup --threads 16 --verify
# Copies all files, 16 parallel workers, verifies each copy

2. Incremental Backup (Every Night)

tallow delta-sync ./important-data /backup/data --mirror --log sync.log
# Syncs changes, removes deleted files from backup, logs details

3. Exclude Build Artifacts (Git, node_modules, target)

tallow delta-sync ./my-project /backup/my-project \
  --exclude-dir .git \
  --exclude-dir node_modules \
  --exclude-dir target \
  --exclude *.log \
  --exclude *.tmp
# Skips large directories, log files, temp files

4. Mirror to NAS (Delete Anything Not in Source)

tallow delta-sync ./my-data \\192.168.1.5\backup --mirror --dry-run
# Preview first
tallow delta-sync ./my-data \\192.168.1.5\backup --mirror
# Confirm with target backup — this deletes extra files

5. Save Job for Reuse

tallow delta-sync ./source /backup/target \
  --mirror --exclude-dir .git --threads 16 \
  --save-job backup-job.toml

# Later, run the same job again:
tallow delta-sync --load-job backup-job.toml
# All flags restored automatically

6. Scheduled Sync (Only 2am-4am)

tallow delta-sync ./data /backup --run-hours 02:00-04:00 --quiet
# Waits if outside window, syncs silently, logs results

7. Verify Integrity After Copy

tallow delta-sync ./large-dataset /remote-backup --verify
# BLAKE3 hash every file after copy (adds ~25% overhead but guarantees safety)

8. Size-Based Filtering

tallow delta-sync ./source /backup --min-size 1048576 --max-size 10737418240
# Skip files < 1MB or > 10GB (useful for very heterogeneous data)

Job File Format (TOML)

# backup-job.toml
[delta_sync]
source = "./important-data"
target = "/mnt/backup"
mirror = true
threads = 16
verify = true
log = "sync.log"

[exclude]
patterns = ["*.log", "*.tmp", "*.bak"]
directories = [".git", "node_modules", "target", ".venv"]

[filters]
min_size_bytes = 0
max_size_bytes = 0
max_age_days = 0

[schedule]
run_hours = "02:00-04:00"
preserve_permissions = true
preserve_owner = false

7. Network Transfer (QUIC Protocol)

send — Code Phrase Transfer (Like croc)

tallow send <file> [--to ip:port]

# Sender: generates code automatically
tallow send file.zip
Code: 742-falcon-ember-crystal
QR code displayed for mobile scanning
# Share the code with your recipient

# Receiver (on different machine):
tallow receive 742-falcon-ember-crystal
# Auto-discovers sender, transfers file over QUIC (TLS 1.3 encrypted)
QUIC PROTOCOLTLS 1.3 ENCRYPTEDBLAKE3 VERIFIED

receive — Listen for Incoming

tallow receive [code] [--listen addr:port]

# Option 1: Wait for code (interactive)
tallow receive
# Enter code: 742-falcon-ember-crystal

# Option 2: Direct listen (known IP)
tallow receive --listen 0.0.0.0:6881
# Sender uses: tallow send file.zip --to 192.168.1.5:6881

Direct Transfer (IP + Port)

# Machine A (receiver): listen on port
tallow receive --listen 0.0.0.0:6881

# Machine B (sender): send directly
tallow send file.zip --to 192.168.1.5:6881
# QUIC protocol, TLS 1.3 encrypted, BLAKE3 verified

Multi-File + Directory Transfer

tallow send file1.txt file2.pdf ./mydir --to 192.168.1.5:6881 --compress
# Multiple files + directories in one transfer
# Auto-compressed with zstd, folder structure preserved (TWD format)

send-text — Text Message Transfer

tallow send-text "Hello from my PC!"
# Sends text directly, BLAKE3 hashed

Relay Server (When Direct Connection Fails)

# Start your own relay (firewall-friendly)
tallow relay --port 6880
# Relay running on relay.example.com:6880

# Send via relay
tallow send file.zip --relay relay.example.com:6880
# File routed through relay, still encrypted end-to-end

discover — Find Local Network Devices

tallow discover
# Output:
192.168.1.5       workpc          port 6881
192.168.1.10      laptop          port 6881
192.168.1.15      server          port 6881

8. Share by Link (No Tallow Needed on Receiver)

The Game Changer

Share files with anyone — they open a link in their browser and download. No Tallow installation, no technical knowledge required.

# Output:
http://192.168.1.5:8432/dl/a7f2.../report.pdf

tallow share onetime.pdf --max-downloads 3

10. Enterprise Transfer Features

Core Enterprise Capabilities

RBAC (5 Roles)

admin, operator, auditor, transfer_only, readonly — permission checks on every action. Compile-time enforcement.

Audit Logging

BLAKE3-chained tamper-evident log. Every transfer logged: who, what, when, where. Non-repudiation.

Webhooks

HMAC-BLAKE3 signed event notifications: transfer_complete, transfer_failed, rate_limited

Transfer Scheduling

Cron-based: "0 2 * * *" (every night at 2am). Active/inactive toggle

Key Rotation

90-day PCI DSS schedule. Version tracking. Auto-rotate with history

mTLS Authentication

Mutual TLS certificate authentication with BLAKE3 fingerprinting

Expiring Transfers

Download count + time limits. Auto-expire after N hours or N downloads. Self-destruct enabled.

Signed Manifests

Non-repudiation: BLAKE3 keyed hash proves who sent what and when

Erasure Coding

Reed-Solomon (10 GiB/s). Survive lost chunks without retransmission

Bandwidth Limiting

--bwlimit 10M — cap transfer speed in Mbps/Kbps/Gbps

View Audit Trail

tallow audit-transfers --format json --save audit.log
# Machine-readable audit: every transfer, every user, every timestamp

Bandwidth Limiting

tallow send large-file.iso --bwlimit 10M
# Cap at 10 Mbps (useful for metered connections)

tallow delta-sync ./source /backup --bwlimit 50M
# Limit sync to 50 Mbps

Watch Mode

tallow watch ./my-project --interval 1000
# Polls every 1000ms, detects added/removed/modified files
# Uses BLAKE3 snapshots for change detection

Retention Policy (Auto-Delete Old Files)

tallow retain ./transfers --days 30
# Deletes files older than 30 days (compliance requirement)

tallow retain ./transfers --days 30 --dry-run
# Preview what would be deleted

13. Troubleshooting

Access Denied on NAS / Remote Path

Problem

Error: Permission denied: \\192.168.1.5\backup

Solution

  1. On Windows: ensure you're logged in with credentials that have NAS access 
    net use \\192.168.1.5\backup /user:domain\username password
  2. On Linux: mount with correct permissions 
    sudo mount -t cifs -o username=user,password=pass //192.168.1.5/backup /mnt/nas
  3. Check NAS shares (some require SMB3, others SMB2)

QUIC Connection Timeout (Firewall Blocking)

Problem

Error: Connection timeout (QUIC port 6881 blocked)

Solution

  1. Use relay server instead: 
    tallow send file.zip --relay relay.example.com:6880
  2. Open port 6881 UDP on both machines (if behind corporate firewall, ask IT)
  3. Use direct HTTP sharing instead: 
    tallow share file.zip --port 8080

Large Directory Scan Performance

Problem

Scanning /mnt/nas (500k files) taking too long...

Solution

  1. Increase parallel threads: 
    tallow delta-sync ./source /backup --threads 32
  2. Exclude large directories: 
    tallow delta-sync ./source /backup --exclude-dir .git
  3. Use --dry-run to preview first (scans only, no copy): 
    tallow delta-sync ./source /backup --dry-run

Encryption Password Recovery

Problem

Forgot password for encrypted file...

Solution

None. By design. AES-256-GCM with Argon2id is unrecoverable. To prevent this:

  • Use a password manager (1Password, Bitwarden, LastPass)
  • Store password securely (encrypted note, secure vault)
  • Test decryption immediately after encryption
  • Keep backups of important passwords (in secure location)

Verify Hash Mismatch After Transfer

Problem

Hash mismatch: expected a7f2c3d4e5f6..., got b1e3d4f5a6b7...

Solution

  1. Retry the transfer (network blip): 
    tallow delta-sync ./source /backup --retries 5 --verify
  2. Check disk health (bad sectors): 
    # Windows
chkdsk C: /F

# Linux
smartctl -t short /dev/sda
  3. Copy to different disk to isolate issue

High Memory Usage With Large Files

Problem

Using 16GB RAM for a 2GB file...

Solution

This is normal for streaming operations with zstd compression. To reduce memory:

  1. Disable compression: 
    tallow delta-sync ./source /backup
# No --compress flag
  2. Use fewer threads: 
    tallow delta-sync ./source /backup --threads 2
  3. Transfer smaller batches at a time
