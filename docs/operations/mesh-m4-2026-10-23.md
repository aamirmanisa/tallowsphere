# Mesh M4: the real wire

Date: 2026-10-23. Status: implemented and verified.

The three decisions the M4 hold required are made below, each with what it costs.
Everything after that is the evidence the claims rest on.

## Decisions

### 1. Transport: a dedicated frame, not the CDP relay

The relay in `src/browser/distributed/relay.rs` multiplexes browser sessions by
target id. It has no concept of a wave, a task, or a lease, so carrying the mesh
over it would put scheduling semantics inside opaque browser payloads — no shared
invariants, no shared tests, and a bug in one plane indistinguishable from a bug
in the other.

`src/mesh/wire.rs` defines a 1 MiB length-prefixed JSON frame with a fixed
canonical byte string for signing: `tallow-mesh/<version>/<kind>/<run_id>/<wave>/<node>/<nonce>/<payload>`.
A dedicated frame is small enough to audit in one sitting, and its failure mode
(oversized or truncated frame) is checked before allocation.

Cost accepted: a second protocol to maintain, and no reuse of relay's NAT
traversal. M4 is a same-network plane; crossing NAT is not solved here and is not
claimed.

### 2. Threat model: every frame signed, control restricted to operators

In-process, the control plane needed no authentication because the caller owned
the process. Across a socket it does:

- **Join and Result** are verified against a per-node allowlist
  (`MeshServer::bind(..., node_keys)`). A node that signs with any other key is
  refused, and the refusal is *said* — a signed `refused` frame with the reason,
  then close. A silent close would let a worker report success after being
  turned away.
- **Welcome** is signed by the coordinator, so a worker knows it reached the
  intended server rather than a listener that will feed it work.
- **Control frames** (`stop`, `inject`) are accepted only from allowlisted
  operator keys (`Trust::allow_operator`).
- **Replay** is refused: nonces are per-run monotonic and keyed
  `run_id:node:kind:nonce`, so a captured `stop` cannot be re-sent into a later
  run or a later wave.

What is *not* claimed: transport confidentiality. The wire is plaintext TCP.
Anything that needs secrecy runs inside an existing tunnel; the mesh does not add
encryption and does not pretend to.

### 3. `simulated` flips per node, after a committed task

A node that joins is not a working part of the mesh. `NodeStatus.simulated` stays
`true` until that node has both joined AND had one result committed by the
coordinator. There is no global flag: one node being real says nothing about
another, and a global flip would let a simulated node claim to be real — the
failure this field exists to prevent.

## Defects found while making the gate pass

These were found by running the tests, not by reading the code.

1. **Unbounded lease reassignment.** A task whose execution time exceeded its
   lease was re-executed forever: every reassignment started a new execution that
   also outlived the lease. The run never completed and never said why. Fixed
   with an attempt cap — past the class limit the coordinator journals
   `TaskFailed` and returns an error.
2. **Reassignment could pick the dead node.** Rotation over joined peers happily
   handed a task back to the node that had just let the lease expire, burning all
   retries without ever meeting a live worker. Fixed by excluding the previous
   holder when another peer exists.
3. **Pure-task seeds depended on the attempt.** A reassigned task got
   `task_seed(..., attempt = new_epoch)`, so a partitioned run committed a
   different checkpoint than an uninterrupted one. `pure` means re-execution is
   identical; the seed is now attempt-independent for pure tasks.
4. **Framing under a read timeout.** `read_exact` on a socket with a timeout can
   consume part of a length prefix; the retry loop then decoded from the middle
   of a frame. Replaced with `FrameReader`, which buffers and only reports "no
   frame yet" at a buffer-empty boundary.
5. **A refused join looked successful.** The worker treated EOF as a clean
   shutdown, so a worker rejected by the allowlist exited 0. Now EOF before
   `welcome` is an error, and an explicit `refused` frame carries the reason.

## Evidence

`tests/mesh_remote.rs` — 3 tests, running real worker processes over TCP:

- `a_partitioned_node_is_fenced_and_its_late_answer_discarded` — two workers;
  w1 frozen with SIGSTOP before the plan starts; six tasks; 300 ms leases. Asserts
  remote checkpoints **equal a local reference run**, at least one reassignment,
  w1 still `simulated` (it never committed) and w2 real, exactly 6
  `task_committed` journal lines, and that thawing w1 adds none.
- `an_untrusted_key_cannot_join` — a worker claiming `w1` with an unauthorised key
  exits non-zero, and no peer is registered.
- `a_run_without_nodes_fails_instead_of_hanging` — refused in under 2 s.

Wire unit tests (`cargo test --lib mesh::wire`): signed round-trip, payload
tampering rejected, replayed nonce refused, unsigned frame refused, oversized
frame refused before allocation, non-operator control refused.

Full lib suite: recorded in the commit that lands this document.

## What is still not real

- `src/stdlib/mesh.rs` (topology: membership, gossip, DHT) remains a simulated
  plane. M4 makes the *execution* plane real; it does not make the topology
  plane's peer table real.
- No NAT traversal, no TLS, no key rotation, no per-tenant isolation.
- No speculation over the wire (deliberate; reassignment covers a peer that is
  gone rather than slow).
